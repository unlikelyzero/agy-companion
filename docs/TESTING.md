# Testing

## Continuous integration

Two GitHub Actions workflows run automatically:

- **`ci.yml`** — runs `npm test` on every push to `main` and every pull request, across Node 18.18/20/22/24 on Ubuntu and Node 18.18/24 on macOS (matching the floor `package.json`'s `engines.node` claims plus the latest). This covers everything mocked (see the next section) and needs no `agy` binary.
- **`agy-release-probe.yml`** — nightly (and on manual dispatch), installs the latest `agy` via the official install script on a hosted runner, confirms the binary runs, and compares `agy --version` against `.github/agy-tested-version` (the last version verified by hand). It also diffs `agy --help` against `.github/agy-help-snapshot.txt`, since a version bump alone doesn't say what actually changed — new/removed flags or subcommands are a more direct signal of what a compatibility pass needs to look at. When either the version or the `--help` output changed, it opens a tracking issue with the diff inline and prompts a manual compatibility pass.

Live integration testing cannot run on hosted CI: agy's only auth is interactive Google OAuth (no API key or service-account path — tracked upstream in google-antigravity/antigravity-cli#78, where Google has said API-key auth is unsupported and points CI users at the separate Antigravity SDK). When the probe files a new-release issue, run the manual checklist below against the new version, then bump `.github/agy-tested-version`.

## What's covered by `npm test`

`npm test` runs Node's built-in test runner (`node --test tests/*.test.mjs`) against everything that does not require a live `agy` binary or a real Google OAuth session:

- **Argument parsing** (`tests/args.test.mjs`): flag/positional parsing, `--key=value`, aliasing, `--` passthrough, quoted raw-argument splitting.
- **State persistence** (`tests/state.test.mjs`): the on-disk job/config store — defaults, config round-trips, job upsert/prune, job file read/write.
- **Job control** (`tests/job-control.test.mjs`): status snapshots (running/latest-finished/recent), job-reference resolution (exact id, unambiguous prefix, ambiguous prefix), cancel/result eligibility rules.
- **Rendering** (`tests/render.test.mjs`): Markdown output for setup, status, review results (well-formed, malformed JSON, schema-mismatched), task results, cancel reports.
- **Process helpers** (`tests/process.test.mjs`): binary-availability detection, command failure formatting, process-tree termination (with an injected `kill` implementation, so no real processes are touched).
- **JSON Schema validation** (`tests/schema-validate.test.mjs`): the local validator against `schemas/review-output.schema.json` — required fields, enums, nested finding objects, numeric ranges.
- **agy transport layer** (`tests/agy.test.mjs`): `runAgyPrompt`'s argument building (including `--model`, `--effort`, `--conversation`, `--output-format`, `--json-schema`), stdout/stderr capture, OAuth-prompt detection (`AgyAuthRequiredError`), missing-binary handling, unsupported-flag handling (`AgyUnsupportedFeatureError`), timeout handling, tail-file writing — all with `child_process.spawn` replaced by an injected fake (`spawnImpl`), never a real `agy` process. Also covers `runAgyStructured`'s parsing of agy's real `--output-format json` envelope shape (`parseAgyEnvelope`), `runAgyText`'s free-form envelope handling (including its raw-stdout fallback when the envelope doesn't parse), and the best-effort git-status-diff touched-files helper (including an unstaged modification, a rename, and a real edit to a tracked file in a live temp repo). `parseAgyEnvelope` is also covered against an envelope whose `response` contains a fenced code block, the shape that broke envelope extraction on 1.2.2.
- **Review snapshotting** (`tests/review-snapshot.test.mjs`): the disposable working-tree copy `/agy:review` and `/agy:adversarial-review` run against — `.git` exclusion, gitignore handling, untracked/staged/unstaged content, agent-instruction file/directory stripping at depth and mixed casing, symlink-escape prevention, snapshot-hash stability, and cleanup. All against a real local git repo (`git init` in a temp dir), not mocked.
- **Provenance** (`tests/provenance.test.mjs`): `buildProvenance`'s field pass-through and all-`null` default shape, and `hashText`'s stability/null-handling. Pure functions, nothing to mock.
- **Git helpers** (`tests/git.test.mjs`): `isGitRepository` and `getHeadCommit` (including the pre-first-commit `null` case) against a real local git repo, not mocked.
- **`agy --help` capability detection** (`tests/agy.test.mjs`): `detectAgyCapabilities` against a verbatim real `agy 1.1.13` help listing (every known flag detected present) and against a stale/minimal listing (missing flags correctly reported `false`), plus null/undefined tolerance. Pure function — the plugin's own capability list is fixed, so this doesn't need to mock `spawn`.
- **State-directory writability** (`tests/state.test.mjs`): `isStateDirectoryWritable` against a normal temp dir (`true`) and against a state path blocked by a file where a directory needs to go (`false`).

Run it with:

```bash
npm test
```

## What's now confirmed against a real, authenticated `agy` install

This plugin was originally built and unit-tested in an environment with no `agy` binary and no Google account available. That gap has been partially closed with a real, authenticated `agy` install (see [`.github/agy-tested-version`](../.github/agy-tested-version) for the exact version last checked), authenticated via the browser/paste-code OAuth flow:

- **`/agy:review`** and **`/agy:adversarial-review`**, foreground, via `--scope working-tree` against a real diff — both produced correctly rendered, schema-conformant results end to end, confirming `--output-format json --json-schema <path>` genuinely works as documented in the README, not just against mocked `spawn` output. Also confirmed against the disposable-snapshot review path (see below): a diff that planted a prompt-injection instruction in `AGENTS.md` was correctly reported as a finding rather than followed, and the large-diff (>256KB) self-collect fallback correctly read the full diff from a file inside the snapshot with no tool-call denials.
- **`/agy:rescue`** (the `task` command), foreground (`--wait`) and background (`--background`) — both produced correct results; `/agy:status` correctly reported a running job's live phase/progress-tail while it was in flight, and `/agy:result` correctly returned the stored output of a completed one.
- **`/agy:cancel`** — confirmed it doesn't just flip a status flag: the underlying `agy` process was actually gone (checked via `ps`) immediately after cancelling.
- **`--conversation <id>`, targeting one specific past job's conversation** — `/agy:rescue` now runs through `agy --output-format json` (`runAgyText`), so it captures a real `conversation_id` like review jobs already did. Confirmed live: ran a task, then a deliberately interleaved unrelated `/agy:review` (to try to hijack agy's own "most recently used conversation" pointer), then `--resume-last` — the resumed job's `conversation_id` matched the *original task's*, not the review's, and its response correctly recalled content only the original task conversation had been given. This replaces the `--resume-last` → `agy --continue` caveat below for any job with a captured `conversation_id`; `--continue` is now only the fallback for a job that predates this capture.
- **`/agy:rescue --write`** — confirmed the `--dangerously-skip-permissions` path runs, returns success, and now correctly lands both a new-file creation and an edit to an existing tracked file inside the target repo. Root-caused and fixed a real bug along the way: a bare `Create a file named X` prompt was landing the file under `~/.gemini/antigravity-cli/scratch/<name>` instead of the repo (reproduced 3/3 with a bare `agy --print` call, independent of agy-companion; editing an *existing* file was unaffected), while explicitly stating the absolute working directory and instructing agy to always use an absolute path for a new file avoided the redirect 4/4 in live trials — `executeTaskRun`'s `buildWriteTaskPrompt` now prepends that guidance to every `--write` run. Confirmed via the real `agy-companion.mjs task --write` CLI path (not just bare `agy`) post-fix: the created file appeared in the repo and `touchedFiles` correctly reported it. Along the way also confirmed a separate, narrower, pre-existing gap in the best-effort touched-files detection: editing a file that was already *untracked* before the run doesn't show up in `touchedFiles`, since `git status --porcelain` reports an untracked path's presence, not a content change to it, so the same line appears in both the before/after snapshot.
- **Provenance metadata** (`scripts/lib/provenance.mjs`) — confirmed live for both a review (`agyVersion`, `conversationId`, `gitHead`, and `scope`/`inputHash`/`reviewedPaths` sourced from the real snapshot all populated correctly) and a task run (`effort: "low"` correctly reflecting an explicit `--effort low` flag, `scope: "read-only"` correctly reflecting no `--write`), and confirmed `/agy:result --json` surfaces the same block back off the stored job record.
- **`/agy:setup --doctor`** — confirmed live: `agy --help` capability detection correctly reported every flag this plugin depends on as present against a real `1.1.13` install, `agy models`/`agy agent` both resolved (14 models, 0 custom agents), the state directory reported writable, the git-repository check reported correctly, and the version-drift check correctly flagged the installed `1.1.13` against the pinned `.github/agy-tested-version` of `1.1.12` — a real, current drift this check would have caught in practice, not just a synthetic one. Confirmed `--doctor --json` surfaces the same `doctor` block.
- **Re-verified against `1.1.17`** (the nightly `agy-release-probe.yml` had flagged 1.1.14 through 1.1.17 as untested): `agy --help` gained two additions since the `1.1.13` snapshot — a new `--input-format` print-mode flag and a new `mcp` subcommand for managing MCP servers — neither of which this plugin depends on, so no capability regression. Re-ran the full live checklist above end to end against the `1.1.17` binary: `/agy:review` and `/agy:adversarial-review` (schema-conformant, correctly flagged a planted stray line and approved a clean change), `/agy:rescue` foreground and background with `/agy:status` reporting live phase/pid, `/agy:cancel` (confirmed via `ps` that a genuinely long-running job's process was gone after cancelling, not just flagged), `--resume-last` correctly recalling the original task's content across a deliberately interleaved `/agy:review`, `--write` both creating a new file and editing an existing tracked file (no scratch-dir redirect), and provenance (`agyVersion: "1.1.17"`) populated correctly for both a review and a task run. `.github/agy-tested-version` and `.github/agy-help-snapshot.txt` bumped accordingly.

- **Re-verified against `1.2.2`** (the nightly probe had flagged 1.1.18 through 1.2.2 as untested, one issue per release). `agy --help` gained two subcommands since the `1.1.17` snapshot — `mic-serve` and `remote-control` — and reworded `--project` to accept a project name as well as an ID. No flag this plugin depends on changed, and `/agy:setup --doctor` reported every one of them still present. Re-ran the live checklist end to end: `/agy:review` and `/agy:adversarial-review` (both schema-conformant, both correctly flagged a planted off-by-one in an untracked file, neither returned the spurious `status: "ERROR"` that 1.1.17 produced on longer runs), background dispatch with `/agy:status` reporting live phase while the job was in flight, `/agy:result`, `--resume-last` correctly recalling a token from the original task's conversation across a deliberately interleaved `/agy:review` (resumed `conversation_id` matched the original task's), `--write` landing both a new file and an edit to an existing tracked file with no scratch-dir redirect, and provenance populated for a review (`scope: "working-tree"`, `inputHash`, `reviewedPaths`) and a task (`effort: "low"`, `scope: "read-only"` / `"write"`).

  Two real bugs surfaced during that pass, both pre-existing rather than 1.2.2 regressions, and both fixed here:

  - **`extractJsonCandidate` mistook a fenced code block inside agy's envelope for the envelope itself.** It tried its markdown-fence pattern before parsing the payload as-is. agy's `--output-format json` envelope is a bare JSON object, and its `response` string contains ``` whenever the model shows a snippet — which a `--write` run confirming a created file does routinely. The fence matched that inner block, `JSON.parse` failed on the snippet, and `runAgyText` fell back to raw stdout: the user saw the entire JSON envelope instead of the reply, and `conversation_id` came back `null`, so the job recorded `conversationResumable: false` and silently lost its targeted `--resume-last` thread. Now the payload is tried as-is first, with the fence and brace-slice paths kept for a model reply that really is JSON wrapped in prose.
  - **`diffGitStatusSnapshots` ate the first character of any modified tracked file's path.** `captureGitStatusSnapshot` trimmed each `git status --porcelain` line, turning ` M existing.txt` into `M existing.txt`, and the diff step then dropped three leading characters — reporting `xisting.txt` as the touched file. Untracked files (`?? created.txt`) came out right by coincidence, which is why the earlier live checks missed it. Lines are now kept untrimmed and the path is read from its fixed column, with rename/copy entries resolving to the destination path.

  One behavior worth recording rather than fixing: `/agy:cancel` does genuinely kill the underlying process, but not instantly. Against a long `--effort high` run the `agy` process was still alive for about five seconds after the cancel returned, then gone — consistent with a SIGTERM-then-SIGKILL escalation. The earlier "gone immediately" note against 1.1.17 was optimistic; check with a few seconds' grace.

- **A reproducible agy `1.1.17` reliability bug in longer/adversarial reviews, filed upstream.** Running `/agy:adversarial-review` against a real third-party PR twice in a row (same diff, fresh conversation each time) produced a `status: "ERROR"` result both times despite the model completing a full, valid `finish()` call with real analysis in the same turn. The two runs failed for two different proximate reasons, both inside agy's own tool-call/task plumbing rather than anything agy-companion does: run 1's transcript (`~/.gemini/antigravity-cli/brain/<conversation_id>/.system_generated/logs/transcript_full.jsonl`) shows agy spawned an internal background subtask via `manage_task`, then cancelled it when the turn ended, and surfaced that as `error: "context canceled"` for the whole run; run 2 failed a `view_file` tool call with `failed to read file: open ~/.gemini/antigravity-cli/scratch/<path>: no such file or directory` — the same scratch-dir path-mirroring behavior documented above for `--write`, but now on a *read*, in a run that never went through agy-companion's disposable-snapshot path at all (it was invoked with `--base`, i.e. branch-diff mode, not working-tree mode). Both runs' `structured_output` was well-formed and usable, but agy's own status flag said `ERROR`, so agy-companion (correctly) refuses to trust it rather than silently accepting error-flagged content. Filed upstream: run 1 as [`google-antigravity/antigravity-cli#848`](https://github.com/google-antigravity/antigravity-cli/issues/848); run 2 turned out to already be tracked as [`google-antigravity/antigravity-cli#826`](https://github.com/google-antigravity/antigravity-cli/issues/826), commented there with the scratch-dir-mirror data point. Not something agy-companion can fix on its own side beyond the fail-open handling it already has (drop the run, don't block the rest of the review panel on it).

None of this covers everything. The rest of this list is still open:

- **The OAuth-prompt detection regex** (`AUTH_REQUIRED_PATTERN` / `URL_PATTERN` in `scripts/lib/agy.mjs`), against a real "Authentication required" prompt. All live tests so far have used an account that was already authenticated, so this path still hasn't fired against real agy output — only against fixtures in the unit tests. (Deliberately not tested by logging out, since that would be disruptive to whoever's running the check.)
- **The stop-time review gate** (`/agy:setup --enable-review-gate`) end-to-end, since it depends on a live `/agy:review`-equivalent run inside the `Stop` hook. (Deliberately not tested in-session, since it can create a long-running loop against whatever session enables it.)

If you're picking this up with a working `agy` install and want to extend this list: the OAuth-prompt path is the most useful gap to close next.
